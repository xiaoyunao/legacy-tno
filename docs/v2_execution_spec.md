## 二、首先重新寻找独立单曝光星表

### 2.1 明确什么产品可以作为输入

本轮需要的是：

> 对单张曝光、单张 CCD 图像独立进行源检测后形成的测量表，包含该次检测的位置、测光和质量信息。

找到候选产品后，必须实际读取样本，检查 HDU、字段、检测数量和生成流程，确认其性质。

以下产品不能直接代替所需输入：

- 在固定参考位置进行的 forced photometry。
- 跨曝光合并后的对象表。
- 仅含标定参考星的测光表。
- PSF 模型文件。
- 只保留某类预选目标的测量子集。

“文件名看起来像星表”或“有一个 `meas` 表”都不足以确认适用。

### 2.2 修正 Legacy 自身 SE 产品的查找方式

第一版使用了类似下面的路径：

```text
calib/decam/se/<曝光分组>/<曝光号>/decam-<曝光号>-S29.fits
```

这个模板与已经核查的 DR11.1.0 源码不符。该版本采用：

```text
calib/se/<image_filename 的目录>/<basename>/<basename>-<CCD>-se.fits
```

应从实际曝光元数据读取 `image_filename`、相机、曝光号和 CCD，使用对应版本 `legacypipe` 生成的 **`im.sefn`** 定位，避免继续猜路径。

依据：

- [SE 文件路径与独立检测代码](https://github.com/legacysurvey/legacypipe/blob/DR11.1.0/py/legacypipe/image.py)
- [SE 输出字段](https://github.com/legacysurvey/legacypipe/blob/DR11.1.0/py/legacypipe/config/common.param)

在已有权限的发布目录、工作目录和缓存中进行有限查找，优先覆盖：

- 两个已有控制目标使用的曝光。
- 原有探索区的曝光。
- 若干 2020 年以后的曝光。
- 不同年份、波段和处理版本的代表样本。

不要无边界递归扫描整个共享文件系统。

还要考虑一个已经确认的事实：Legacy 零点处理流程会在合并 PSFEx 产品成功后删除逐 CCD 的 SE 中间表。因此，必须分别记录“流水线生成过”“当前目录保留着”“公开发布了”这三种状态。[中间文件清理代码](https://github.com/legacysurvey/legacypipe/blob/DR11.1.0/py/legacyzpts/legacy_zeropoints.py)

若找到了 SE 表，继续检查它的天体测量和测光标定状态。**保留了检测表，不等于其中的坐标和流量已经满足最终科学分析要求。**

若未找到，结论应写成“在这些目录、版本和曝光中未找到”，并保留检查清单。

### 2.3 同时接入已经确认可用的 NSC DR2

这条路线不必等待 Legacy 内部目录排查结束。

使用：

- `nsc_dr2.exposure`
- `nsc_dr2.chip`
- **`nsc_dr2.meas`**

主检测输入来自 `meas`。NSC 官方说明，它从逐张 CCD 的独立 SExtractor 检测生成测量，再进行标定和跨曝光对象关联；DR2 提供 AUTO／孔径测光。

已经实际验证过的接入样本是：

```sql
SELECT exposure, expnum, instrument, mjd, filter, exptime, nmeas
FROM nsc_dr2.exposure
WHERE instrument = 'c4d'
  AND expnum = 339232;
```

对应曝光：

```text
c4d_140720_003419_ooi_g_v1
```

可以读取真实测量：

```sql
SELECT measid, objectid, exposure, ccdnum, mjd,
       ra, dec, raerr, decerr,
       mag_auto, magerr_auto, flags
FROM nsc_dr2.meas
WHERE exposure = 'c4d_140720_003419_ooi_g_v1'
LIMIT 5;
```

第一版 14 张审计样本中，已经有 10 张在 NSC 曝光表找到对应记录。将这些作为接入检查，随后扩展到全部控制场和拟选盲搜区域。

匹配时使用 **相机／仪器 + EXPNUM**，再核对时间、滤光片、曝光时间和 CCD。不要要求完整文件名一致，因为同一曝光可能有 `_v1`、`_ls9`、`_ls10` 等不同处理版本标识。

先取得曝光元数据，再按所需曝光分批读取检测。不要下载或扫描整个 `meas` 表。实现缓存、有限重试和断点续传，避免重复查询同一曝光。

### 2.4 明确年份缺口

当前确认的 NSC DR2 DECam 覆盖截至 **2019-11-16**。原项目的 2021 年探索区不能直接用 NSC DR2 替换输入。

因此：

- 2019 年以前的曝光，优先检查 NSC 与 Legacy 的交集。
- 2020 年以后的曝光，继续查 Legacy 保留的 SE 产品及其他可访问的独立检测表。
- 未找到现成表的曝光，保留明确缺口，必要时继续使用已有 SEP 作为补充。
- 不等待尚未确认公开可用的后续 NSC 版本。

其他数据来源可以并行调查，但不能阻塞已有 NSC 子集的运行。

| 类别 | 必须记录的信息 |

| 物理曝光 | 相机、EXPNUM、CCD、时间、波段、曝光时间 |

## 四、统一检测表，先做好时间、误差与重复观测处理

### 4.1 建立统一接口

尽量保留现有程序结构，通过输入适配层支持不同星表。

统一记录至少包括：

- 原始测量 ID、数据来源和版本。
- 物理曝光 ID、相机、CCD。
- 原始时间、曝光时长、曝光中点和时标。
- RA、Dec、位置误差及坐标约定。
- 滤光片、星等或流量、误差、测光类型。
- 原始质量标志、形态、FWHM；可用时保留像素坐标。
- 每个筛选步骤的结果和原因。

不要丢失原始字段的含义，也不要把不同产品的数值放进同一列后默认其定义相同。

### 4.2 必须处理的几个问题

**时间：** NSC 曝光时间需要转换为中点：

\[
\mathrm{MJD}_{\rm mid}
=
\mathrm{MJD}_{\rm start}
+
\frac{\mathrm{EXPTIME}}{2\times86400}.
\]

保存原始值，明确 UTC 与轨道程序使用时标的转换，避免重复加半曝光时间。

**位置误差：** NSC 的 `raerr`、`decerr` 单位是角秒。进入轨道拟合前，需要核对接口要求的是 RA 角度误差还是切平面 \(\alpha\cos\delta\) 误差，避免重复乘除 \(\cos\delta\)。上述时间和单位处理也有实际太阳系数据接入实现可供交叉核对。

**测光：** NSC 已有标定测光，不能再对其星等重复应用 Legacy CCDZPT；明确标注 AUTO／孔径类型。

**天体测量：** 先检查坐标与 Gaia 的残差，再决定是否需要额外修正。不能在不了解原有标定的情况下叠加另一套 Legacy 偏移。

**重复产品：** 同一物理曝光中的同一源，如果同时有 NSC、Legacy SE 和 SEP 测量，只能作为一次独立观测参与主拟合。其他版本用于比较，不能人为增加观测数或缩小误差。

**对象编号：** NSC 的 `objectid` 不能直接作为 TNO 的跨历元身份。

### 4.3 做同曝光质量比较

优先使用已有 SEP 缓存，对代表性 CCD 比较：

- 检测数量和星等分布。
- 位置差及其随星等、CCD 位置的变化。
- 测光差及测光定义造成的差异。
- 质量筛选后的保留比例。
- 控制目标的检测情况。

比较应同时报告“共同曝光集合”和各数据源的额外覆盖。不能把曝光集合不同造成的差异，全部解释成提源方法的改进。

本轮不需要重新开发全套 PSF 测光流程。对已有合格测量，直接使用；对最终候选再考虑精细测量。

## 五、重新检查静态源排除，保护真正的移动源

这里要把两种“已知源”分开：

- 恒星、星系等静态背景：在关联前处理。
- 已知太阳系天体：在候选形成后识别，并用于验证。

### 5.1 保留可追溯的筛选标志

在 NERSC 保留所选曝光的原始测量缓存。各类质量问题和静态证据分别打标，不要直接覆盖原表。

至少分成：

| 类别 | 处理原则 |
|---|---|
| 明确无效检测 | 按产品位定义处理坏像素、严重截断、饱和等问题 |
| 强静态证据 | 可从主关联池排除，但保留原因与回查能力 |
| 静态邻近或混叠歧义 | 保留标志，进入较宽松分支或轨道预测回查 |
| 未发现静态证据 | 进入主要运动关联 |

不要一律要求 `flags == 0`，也不要对暗源硬性要求很高的 `class_star`。先查清各字段和位的定义。

### 5.2 静态匹配规则

Gaia 匹配要传播到观测历元，结合位置误差、匹配唯一性和必要的自行／视差处理。

Legacy Tractor／Sweep 或 NSC 对象表的匹配可以作为证据，但**单次位置接近不能直接判死为静态源**。需要结合独立多历元的位置稳定性、测量质量和可能的混叠。

尤其不能：

- 先要求 `ndet ≥ 2` 再读取 NSC 测量。
- 因为检测有 `objectid` 就删除。
- 因为与 coadd 源接近就删除。
- 要求不同波段、不同时刻的星等完全一致。

### 5.3 同时控制计算量与漏检

可以先用较干净的检测池生成候选，再用初步轨道到更宽松的原始测量池中回查。

但必须说明这种策略的边界：**如果一个真实目标的所有检测都被分到歧义池，单靠干净种子回查仍然找不到它。**

因此，在有限试点中加入歧义分支的验证，统计它带来的新增回收和计算成本。对控制目标逐点检查，明确是否有真实测量被静态清除误删。

## 六、先做两个不同的回收实验

### 6.1 实验 A：星表里有没有目标

沿用 **2013 TV158、2017 OF201**，并检查原来未回收的控制对象。

利用独立星历，对每个预期历元判断：

- 是否有对应曝光和 CCD 星表。
- 星历位置是否落在有效区域。
- 附近是否有实际检测。
- 检测是否通过质量筛选。
- 是否被静态源处理排除。

将缺失明确分成：

1. 没有可用曝光／CCD 产品。
2. 有产品，但没有目标检测。
3. 有检测，被后续筛选排除。

这个实验验证的是检测与筛选，不能称为盲关联成功。

### 6.2 实验 B：从完整候选池盲回收

给关联程序输入控制场的完整候选检测池，不用目标的预测位置、速度或已知轨道生成其候选。

正式运行前冻结参数，运行后再核对已知身份。

沿用并完善现有逐阶段统计：

| 阶段 | 含义 |
|---|---|
| A | 几何覆盖到的已知目标 |
| B | 独立星表中实际存在检测 |
| C | 检测通过质量及静态源处理 |
| D | 存活测量在冻结条件下具有关联机会 |
| E | 完整候选池中的盲搜成功回收 |
| F | 仅在星历引导的诊断旁支中找到 |

每个阶段都给分子、分母和失败原因。因计算截断而没搜完的对象，单独列为未完成，不能与真实漏检混在一起。

两个控制目标用于确认链路。随后尽量扩大到覆盖区域内其他已知 TNO；样本少也要报告已有结果，不要因样本不足而停止统计。

## 七、复用并修正现有关联程序

### 7.1 适应实际采样

先统计每个区域的：

- 独立曝光数和夜数。
- 夜内重访情况。
- 跨夜间隔。
- 单季和跨季基线。

如果多数夜只有一张曝光，就不能要求先构造同夜三点 tracklet。

优先继续使用现有的距离假设、视差约束和跨夜关联模块。本轮不要求从头实现 THOR、HelioLinC 或另一套完整框架。

### 7.2 明确搜索范围

本轮可以继续使用 v1 的 **30–300 au 工程范围**，但必须说明：

- 指的是哪个参考时刻的距离。
- 搜索内部使用的是日心距离、观测者距离还是切平面深度。
- 这些量如何对应最终轨道结果。

不要把当前距离与轨道半长轴混为一谈，也不要为降低计算量悄悄缩窄成只适合两个控制目标的范围。

短时间线性运动可以用于种子生成；跨数周、数月的检验应包含观测者运动和视差。跨季增长使用轨道预测，不能用一条直线加大容差代替。

### 7.3 候选生成、增长与去重

关联流程应能：

1. 生成跨夜种子。
2. 用距离和动力学约束降低组合数量。
3. 增长到更多独立夜。
4. 进行轨道拟合。
5. 回查更宽松的检测池。
6. 保留合理的竞争关联。
7. 合并重复候选。

允许缺测，不要求每张曝光都有检测。

对于 OF201 这类只有少量历元的控制实验，允许保留低观测数分支，但必须与证据更充分的候选区分，不能通过降低门槛后把所有结果都归为可靠轨道。

### 7.4 解决第一版的搜索截断问题

**本轮至少要有一组预先固定的试点，把声明的距离箱和空间分片全部处理完成。**

如果组合数过多，优先：

- 优化空间索引和候选剪枝。
- 拆分空间、时间窗口或距离箱。
- 设置合理的分区重叠和运动缓冲区。
- 使用可恢复的分片作业。

若仍无法完成，应缩小试点范围后重新完整运行。

可以保留 SNR 较高的性能对照，但不能把 SNR≥8 的结果当成原 SNR≥5 配置已经完成。

达到 pair、triplet、时间或内存上限的分片必须记录为未完成。Slurm 显示 `COMPLETED`，也不自动等于科学搜索完成。

## 八、轨道拟合与跨季增长

### 8.1 保留现有拟合器，增加独立验证

现有拟合器可以继续使用，同时检查：

- 曝光中点和时标。
- 实际观测站位置。
- 光行时。
- 参考系与坐标定义。
- 位置误差及权重。
- 摄动力模型。

在控制目标上，使用独立实现或独立星历核对。可以优先尝试命令行 Find_Orb，它支持读取 MPC／ADES 天体测量并输出轨道和星历。

若独立软件暂时安装失败，记录原因，继续完成其他可运行部分；但不能把尚未交叉验证的结果描述成已通过验证。

与 Horizons 比较时，明确观测站、时间尺度和天测坐标约定，避免把不同定义的天球位置直接相减。[Horizons 官方说明](https://ssd.jpl.nasa.gov/horizons/manual.html)

### 8.2 每条轨道必须输出的结果

至少包括：

- 实际参与拟合的测量 ID。
- 独立曝光数、夜数、观测弧长。
- 每条观测的东西、南北方向残差和归一化残差。
- RMS、χ²、自由度与误差模型。
- 轨道状态、参考时刻、参考系。
- 距离及可估计的轨道参数范围。
- 是否受到先验、参数边界或明显退化影响。

短弧不能只报一个最佳半长轴和偏心率。对约束不足的对象，明确标成短弧暂定关联，给出可接受解范围或预测不确定度。

不能仅凭低 RMS、高偏心率或很大的最佳半长轴，把候选解释为特殊远距离天体。

### 8.3 改进留出检验

有足够夜数时，进行整夜留出预测。

每次检验只使用训练夜重新初始化和拟合。不要把包含留出夜信息的完整轨道作为唯一初值，再把结果称为独立预测验证。

留出后观测不足时，明确写“无法进行有意义的该项检验”，不要伪造一个通过指标。

### 8.4 实际尝试跨季延长

对控制目标和较可信的匿名候选：

1. 从当前弧段得到轨道与预测不确定度。
2. 搜索其他季节可用曝光。
3. 在预测区域内查询已有独立检测。
4. 检查可能关联及竞争解。
5. 加入支持点后重新拟合。
6. 用其他未参与点检验预测。

至少对两个控制目标做一次实际跨季增长尝试，报告成功与否及原因。

若需要在缺失星表的少量曝光上补充测量，可以调用现有提源程序。星历引导的强制测光只能作为单独诊断，不能混入独立检测回收统计。

## 九、已知天体识别、伪关联对照与候选图像检查

### 9.1 扩大已知天体核对范围

目前身份检查主要依赖 DES 发布目录。本轮需要接入更完整、版本明确的已知小天体轨道来源，并记录获取日期与覆盖范围。

对形成的候选按多历元位置和运动一致性检查身份，不只匹配某一张曝光。

结果至少分成：

- 已知天体的可靠匹配。
- 存在竞争身份或成员污染。
- 尚未识别。
- 明显伪关联。

**“未匹配到已知库”只能称为未识别候选。**

### 9.2 做有限但真实的伪关联对照

保留整夜重排等对照实验，尽量保持夜内相对时间、检测密度和空间结构，破坏真实跨夜运动关系。

使用与真实运行相同的主要配置，分别报告是否完整运行、生成多少链、多少通过拟合和后续检查。

这种实验用于判断组合背景，不能直接等同于精确的假发现率。

### 9.3 候选阶段再进入图像

为较可信的未识别候选，以及典型失败案例生成：

- 各历元科学图像小图。
- 检测位置和轨道预测位置。
- 对应 DQ／权重信息。
- 邻近恒星、星系、亮星光晕和条纹情况。

优先检查当前候选池中证据最强的对象；若数量很少，就全部检查。

在 NERSC 读取图像，本地同步结果图。无需为此重新进行全量图像提源。

## 十、选择一个真正独立的小规模盲搜试点

控制实验之外，需要完成至少一组独立盲搜。

### 选区原则

根据以下信息选区：

- 现成星表的真实覆盖。
- 独立夜数与时间间隔。
- 曝光深度和质量。
- 背景源密度。
- 跨季增长机会。
- 预计计算成本。

选区和配置在查看候选结果前冻结，不围绕已知目标位置调整。

优先考虑非 DES 提案曝光较多的区域，同时报告与 DES 天区的重叠。排除了 DES 提案曝光，不等于天空区域未被 DES 搜索过。

### 与原 2021 年探索区的关系

如果原 2021 年区域找到了合格的内部星表，可以继续使用。

如果没有，新增一个 NSC 覆盖期内的独立区域，明确记录为新的试点。保留原区域作为后续年份的数据缺口，不能将其悄悄换掉后声称完成了原任务。

### 运行规模

先选择能完整处理的小区域，再依据实测成本扩大到多个区域。面积目标可以逐步达到数平方度，但优先保证：

- 声明的距离范围确实搜索完成。
- 核心区和读取缓冲区定义明确。
- 分区边界的运动轨迹没有被系统性截断。
- 输出真实的面积、时间范围、质量条件和运行状态。

**零候选也是结果，但必须来自一个完成了的、定义清楚的搜索。**

## 十一、做必要的完整度检查，不让它阻塞实际结果

本轮分别报告三类指标：

### 11.1 产品覆盖

计划曝光中，有多少具备可用的独立检测表，以及因此损失了哪些年份和观测机会。

### 11.2 已知目标回收

报告几何覆盖、星表检出、清理保留、关联机会和盲回收的逐阶段结果。

按星等、运动速度、夜数、弧长等分组；样本少时给出原始计数和不确定度。

### 11.3 星表级注入

在真实背景检测池中注入模拟运动轨迹，重新经过筛选、关联和拟合。

要求：

- 使用实际曝光时间和 CCD 足迹。
- 覆盖声明的距离、运动与采样条件。
- 小批注入，避免明显增加源密度。
- 真值只用于评分，不能提供给搜索。
- 分别统计静态处理、关联和轨道筛选造成的损失。
- 对噪声和缺测模型明确标为假设。

可以先完成约百条量级的模拟轨迹，再按计算成本扩大。实际完成多少就报告多少，不因未达到理想样本量而不交付已有结果。

**星表级注入测量的是在给定检测条件下的处理效率，不能代替图像级检出完整度。** 本轮不强制完成全套像素注入，但不能将条件回收率写成巡天绝对完整度，也不能用静态位置的多夜覆盖面积直接代替移动天体的有效搜索面积。

## 十二、本轮必须交付的结果

### 统计表

| 结果 | 需要回答的问题 |
|---|---|
| 星表产品与覆盖表 | 实际找到了什么，哪些曝光和 CCD 可用？ |
| 同曝光对照表 | NSC／Legacy SE／SEP 的检测、位置和测光有何差异？ |
| 控制目标逐历元表 | 每个预期观测在哪一步保留或丢失？ |
| 逐阶段回收表 | 检测、清理、关联和测轨各损失多少？ |
| 搜索完成状态表 | 哪些空间、时间和距离分片确实完成？ |
| 候选汇总表 | 夜数、弧长、残差、轨道约束、身份和证据等级如何？ |
| 跨季增长表 | 找回了哪些额外历元，轨道约束改善多少？ |
| 成本统计表 | 查询、筛选、关联、拟合分别用了多少时间和资源？ |

### 结果图

至少包括：

1. 星表覆盖与缺口的天区图、年份分布。
2. 试点的曝光时间采样和夜数分布。
3. 同曝光位置差、测光差随星等的变化。
4. 源筛选各阶段数量及控制目标保留情况。
5. 已知目标轨迹、轨道残差和留出预测。
6. 已知目标及注入回收随相关变量的变化。
7. 未识别候选的轨迹与多历元图像小图。
8. 各距离箱的计算量与完成情况。

图注要写清数据子集、配置、分母和限制。保持现有项目的绘图风格，并补齐有科学解释价值的图。

### 程序与可重复运行

保留实际运行命令、完整配置、代码版本、输入版本、作业编号与日志。提供从星表接入到最终报告的可恢复入口，不要求每次重跑全部阶段。

最终报告必须明确回答：

- 现成星表解决了多少重复提源工作？
- 哪些曝光仍需其他产品或自己提源？
- 两个控制目标以及扩展样本回收得怎样？
- 当前主要瓶颈位于输入、静态处理、关联还是测轨？
- 独立盲搜实际完成多大范围，得到什么？
- 有无值得继续检查的未识别候选？
- 跨季增长是否可行？
- 下一轮扩大运行最先需要解决什么？

---

**执行顺序是：星表查找与覆盖审计 → 统一检测输入 → 同曝光比较和控制回收 → 修正筛选与关联 → 完整小规模盲搜 → 身份与图像核验 → 跨季增长 → 统计和报告。**

发现某条数据路线不可用时，记录缺口，继续推进已经可用的部分。允许阶段性结果不理想，也允许最终没有新候选；本轮必须把失败发生在哪里查清楚，并留下能够复跑和继续扩展的程序与真实结果。
